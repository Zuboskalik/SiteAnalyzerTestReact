## Phase 2 — Математический модуль (Chunking, Cosine Similarity, Embeddings Service)

- [ ] **P2-1. Утилита `cosineSimilarity`**
  Файлы: `src/services/similarity/cosineSimilarity.js`.
  DoD: Функция принимает два числовых массива одинаковой длины и возвращает число в диапазоне `[-1, 1]`; для идентичных векторов возвращает `1`, для ортогональных — `0`; покрыта unit-тестами (см. P2-9).

- [ ] **P2-2. Утилита классификации зон релевантности**
  Файлы: `src/utils/relevanceZones.js`.
  DoD: Функция принимает `similarity` (0–1 или 0–100%) и возвращает `'highly_relevant' | 'broad_match' | 'noise'` строго по порогам из п. 3.4 спецификации (>65%, 43–64%, 0–42%); граничные значения (43%, 65%) проверены тестом.

- [ ] **P2-3. Утилита `chunkText`**
  Файлы: `src/services/chunking/chunkText.js`.
  DoD: Функция принимает сырой текст и параметры стратегии (например, максимальная длина чанка), возвращает массив объектов вида `{ text, index, charStart, charEnd }`, где `charStart`/`charEnd` корректно указывают на позицию фрагмента в исходной строке (проверка: `text.slice(charStart, charEnd) === chunk.text`).

- [ ] **P2-4. Контракт `EmbeddingProvider`**
  Файлы: `src/services/embeddings/EmbeddingProvider.js`.
  DoD: Задокументирован единый интерфейс (JSDoc) с методом `embed(texts: string[]): Promise<number[][]>`; все последующие провайдеры (P2-5–P2-7) реализуют этот сигнатурный контракт.

- [ ] **P2-5. `MockEmbeddingProvider`**
  Файлы: `src/services/embeddings/mockEmbeddingProvider.js`.
  DoD: Возвращает детерминированные псевдослучайные векторы фиксированной размерности; при одинаковом входном тексте всегда возвращает одинаковый вектор (проверка равенства при двух последовательных вызовах с одним текстом).

- [ ] **P2-6. `TransformersEmbeddingProvider` (`@xenova/transformers`)**
  Файлы: `src/services/embeddings/transformersEmbeddingProvider.js`.
  DoD: При вызове `embed(['test'])` в браузере (без сетевого ключа) модель загружается и возвращает числовой вектор ожидаемой размерности; повторный вызов после первой загрузки модели не вызывает повторную полную загрузку весов (проверка по логам/Network tab — используется кэш).

- [ ] **P2-7. `OpenAIEmbeddingProvider` (`text-embedding-3-small`)**
  Файлы: `src/services/embeddings/openaiEmbeddingProvider.js`.
  DoD: При наличии валидного API-ключа (передаётся параметром, не хардкодится) запрос к OpenAI Embeddings API возвращает вектор; при отсутствии/невалидном ключе функция выбрасывает понятную ошибку, которая может быть поймана вызывающим кодом (не «тихий» сбой).

- [ ] **P2-8. Оркестрация `analysisPipeline`**
  Файлы: `src/services/analysisPipeline.js`.
  DoD: Функция принимает входные параметры формы (текст/URL-текст, keyword, meta-поля, выбранный `EmbeddingProvider`) и возвращает объект, соответствующий типу `AnalysisResult`: текст разбит на чанки (P2-3), для keyword и каждого чанка вычислен embedding (через переданный provider) и `similarity` (P2-1), каждому чанку проставлена `relevanceZone` (P2-2).

- [ ] **P2-9. Unit-тесты математического модуля**
  Файлы: тесты для `cosineSimilarity`, `relevanceZones`, `chunkText` (например, через Vitest).
  DoD: `npm run test` (или аналог) проходит зелёным для всех тестов модуля; включены граничные случаи (нулевые векторы, пустой текст, точные пороги зон релевантности).

- [ ] **P3-2. Переключатель источника контента URL / Текст**

- [ ] **P3-8. Индикация состояния загрузки и ошибок анализа**
  DoD: Во время выполнения `analysisPipeline` в UI отображается индикатор загрузки (spinner/skeleton); при выбросе ошибки (например, невалидный OpenAI-ключ из P2-7) пользователю показывается читаемое сообщение об ошибке вместо «зависшего» состояния формы.

## Phase 5 — Модуль Comparison Map (векторный граф с Tether-слайдером)

- [ ] **P5-1. Установка React Flow**
  DoD: Пакет добавлен в `package.json`; минимальный граф с двумя тестовыми узлами и одним ребром рендерится в браузере с работающим pan/zoom.

  DoD: Функция принимает список `PageVector` (включая `similarityToKeyword`) и возвращает координаты `{x, y}` для каждого узла, где расстояние от центра (позиции keyword-узла) монотонно убывает с ростом similarity; координаты не пересекаются полностью (базовое угловое распределение) при ≥10 узлах на входе.

- [ ] **P5-5. Кастомное ребро Tether**
  DoD: Зарегистрирован кастомный тип ребра, соединяющего keyword-узел с каждым узлом страницы; толщина и/или прозрачность линии визуально коррелирует со значением similarity этой пары (выше similarity — заметнее линия).

- [ ] **P5-6. `ComparisonVectorMap.jsx` — сборка графа из данных стора**
  Файлы: `src/components/visualizations/ComparisonVectorMap.jsx`.
  DoD: Компонент строит полный список узлов (`targetPage` + все страницы из `competitors`) и рёбер (`keyword ↔ каждая страница`), используя P5-2–P5-5; при подстановке mock-данных из P1-9 граф отображается в браузере со всеми ожидаемыми узлами.

Закрывает критерий п. 4.1 спецификации (Tether threshold filtering).

- [ ] **P5-9. Легенда графа**
  DoD: Под/над графом отображается легенда, сопоставляющая цвет точки с названием сайта (целевой сайт + каждый конкурент по имени и цвету из `CompetitorSite.color`).

- [ ] **P5-10. Проверка pan/zoom и общей отзывчивости графа**

## Phase 6 — Deep AI Analysis и детализация чанков

- [ ] **P6-1. `deepAnalysisService` — mock-генератор**
  Файлы: `src/services/deepAnalysisService.js`.
  DoD: При режиме Mock функция возвращает объект `DeepAnalysis` (Executive Summary, Missing Entities, Suggestions) на основе входных `AnalysisResult` (например, простые эвристики по распределению зон релевантности), без сетевых вызовов.

- [ ] **P6-2. `deepAnalysisService` — вызов реального AI-анализа**
  DoD: При режиме, отличном от Mock (и наличии необходимого API-доступа), функция формирует запрос к LLM с промптом, включающим keyword, meta-поля и содержимое чанков, и парсит ответ в структуру `DeepAnalysis`; при ошибке сети/парсинга выбрасывает понятную ошибку, перехватываемую UI (аналогично P3-8).

- [ ] **P6-3. Карточка Executive Summary**
  Файлы: `src/components/analysis/DeepAnalysisCards.jsx`.
  DoD: Компонент отображает текст `deepAnalysis.executiveSummary` в отдельной карточке (Shadcn `Card`); карточка видна в браузере при заполненных mock-данных.

- [ ] **P6-4. Облако тегов Missing Entities**
  DoD: Каждый элемент `deepAnalysis.missingEntities` рендерится как тег во flex-обёртке; при большом количестве сущностей (проверено на ≥15 элементах) блок не ломает layout страницы (перенос строк работает корректно).

- [ ] **P6-5. Список Actionable Optimization Suggestions**
  DoD: Каждая рекомендация из `deepAnalysis.suggestions` отображается с заголовком, описанием и визуальным индикатором приоритета (`high`/`medium`/`low` — например, цветной бейдж); порядок отображения — от высокого приоритета к низкому.

- [ ] **P6-6. `SourceTextPanel.jsx` — отображение полного текста с границами чанков**
  Файлы: `src/components/content/SourceTextPanel.jsx`.
  DoD: Компонент рендерит полный исходный текст, визуально размеченный по границам `chunk.charStart`/`chunk.charEnd` (например, `<span>` на чанк); при наведении на чанк в тексте курсор/стиль показывает, что фрагмент кликабелен/связан с графиками.
