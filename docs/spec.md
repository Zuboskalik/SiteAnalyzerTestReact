# Semantic Relevance & Space Analyzer — Спецификация

## 1. Цель проекта

Создать одностраничное React-приложение (SPA) для семантического анализа контента веб-страниц относительно целевого ключевого слова и построения визуальных семантических карт, показывающих смысловую близость контента (Vector Space / Proximity Map).

Приложение должно помогать SEO-специалистам и контент-стратегам оценивать:
- насколько текст страницы релевантен целевому запросу и связанным темам;
- какие смысловые сущности (entities) отсутствуют в контенте;
- как страница соотносится по смыслу со страницами конкурентов;
- какие конкретные фрагменты текста (чанки) требуют доработки.

## 2. Пользовательские роли и контекст использования

- Основной пользователь: SEO-специалист / контент-стратег / копирайтер.
- Работа ведётся сессионно: пользователь вводит один анализ за раз (одна страница/текст + список конкурентов), просматривает визуализации и рекомендации.
- Приложение может использоваться как в демонстрационном режиме (без реальных API-вызовов), так и в режиме реальных данных.

## 3. Функциональные требования

### 3.1 Форма ввода данных для анализа

Экран/секция ввода параметров анализа должна содержать поля:

- **Target Keyword** — целевое ключевое слово или фраза (обязательное поле).
- **Источник контента** — переключатель между:
  - **URL** — ссылка на анализируемую страницу;
  - **Текст** — прямой ввод текста в textarea.
- **Target Audience** — описание целевой аудитории (свободный текст или выбор из предустановленных категорий).
- **Content Purpose** — цель контента (например: информационный, коммерческий, транзакционный, навигационный — выбор из списка).
- **Website Niche** — ниша/тематика сайта (свободный текст или выбор из предустановленных категорий).
- Опционально: список URL конкурентов для сравнительного анализа (см. п. 3.5).

Форма должна валидировать обязательные поля перед запуском анализа и отображать понятные сообщения об ошибках.

### 3.2 Обработка контента (Chunking & Embeddings)

- **Разбиение текста на чанки (Chunking)**: исходный текст (введённый вручную или полученный по URL) разбивается на смысловые фрагменты (например, по абзацам, предложениям или блокам фиксированной длины — конкретная стратегия чанкинга должна быть настраиваемой или документированной как параметр).
- **Вычисление эмбеддингов**: для целевого ключевого слова и для каждого чанка вычисляется векторное представление (embedding).
- **Вычисление Cosine Similarity**: для каждого чанка вычисляется косинусное сходство между его эмбеддингом и эмбеддингом целевого ключевого слова. Результат — числовое значение релевантности (0–100% или 0–1) для каждого чанка.
- Промежуточные и итоговые результаты (список чанков с текстом, координатами/векторами и значениями similarity) должны быть доступны для использования во всех визуализациях ниже.

### 3.3 Визуализация 1 — Semantic Proximity Map (Radar / Точечный граф)

- Центральная точка графа — целевое ключевое слово (Target Keyword), визуально выделена.
- Вокруг центра располагаются точки, представляющие чанки контента (и/или отдельные страницы, если анализируется несколько источников).
- Расстояние точки от центра отражает степень семантической близости к ключевому слову: чем ближе к центру — тем выше релевантность (cosine similarity).
- Возможна разбивка на концентрические зоны/кольца, соответствующие уровням релевантности (см. пороги в п. 3.4).

### 3.4 Визуализация 2 — Semantic Relevance Dashboard (линейный график)

- Линейный график, отображающий значение релевантности (cosine similarity, %) последовательно по чанкам контента (например, по оси X — порядковый номер/позиция чанка в тексте, по оси Y — % релевантности).
- Визуальное разделение на три зоны релевантности по пороговым значениям:
  - **Highly Relevant**: > 65%;
  - **Broad Match**: 43–64%;
  - **Noise**: 0–42%.
- Зоны должны быть визуально различимы (цвет/фон/маркеры) на графике.
- График должен давать возможность быстро оценить, какая доля контента попадает в каждую зону.

### 3.5 Граф конкурентного анализа (Comparison Map)

- Визуализация сравнивает целевую страницу с страницами конкурентов относительно одного или нескольких ключевых слов.
- Элементы графа:
  - **Ключевое слово** — отображается золотым ромбом (уникальная форма/цвет, чтобы выделяться среди остальных узлов).
  - **Страницы анализируемого сайта** — точки одного цвета.
  - **Страницы конкурентов** — точки другого цвета (возможна цветовая дифференциация по каждому конкуренту отдельно).
  - **Линии связи (Tether)** — соединяют ключевое слово со страницами, показывая факт и силу семантической связи.
- **Фильтрация по порогу косинусного сходства (Tether threshold)**: пользователь управляет порогом (например, через слайдер), ниже которого связи (tether) скрываются из графа — позволяет отсекать слабые/незначимые связи и фокусироваться на сильных совпадениях.

### 3.6 Раздел Deep AI Semantic Analysis

Раздел с карточками, генерируемыми на основе AI-анализа контента:

- **Executive Summary** — краткое текстовое резюме семантического анализа страницы (сильные и слабые стороны, общая оценка релевантности).
- **Missing Entities** — облако тегов (tag cloud) с сущностями/темами/понятиями, которые ожидаются в тематике, но отсутствуют в анализируемом контенте.
- **Actionable Optimization Suggestions** — список конкретных, практических рекомендаций по улучшению семантической релевантности контента (например, какие темы добавить, какие фрагменты переписать/расширить).

## 4. Критерии приёмки

### 4.1 Интерактивность визуализаций

- Все графики (Proximity Map, Relevance Dashboard, Comparison Map) поддерживают **hover** — при наведении на точку/узел/сегмент отображается всплывающая подсказка (tooltip) с деталями (например: текст чанка или его фрагмент, значение similarity, URL страницы).
- Comparison Map поддерживает **фильтрацию по порогу (Tether threshold)** в реальном времени: изменение порога немедленно обновляет отображаемые связи без перезагрузки страницы.
- Relevance Dashboard и/или Proximity Map поддерживают **клик по чанку**, при котором соответствующий фрагмент текста подсвечивается в отображении исходного контента (например, в панели с полным текстом страницы).

### 4.2 Режимы работы с данными

- **Демо-режим (Mock data)**: приложение может выполнять полный цикл анализа и отображать все визуализации на основе заранее подготовленных/сгенерированных тестовых данных, без обращения к внешним API. Используется для демонстрации функциональности без затрат на реальные вычисления эмбеддингов.
- **Режим реальных данных**: приложение может получать эмбеддинги через реальные API — OpenAI Embeddings API и/или локальное вычисление через Transformers.js (в браузере, без внешнего API-ключа).
- Переключение между режимами должно быть доступно пользователю в интерфейсе (например, переключатель настроек), с явным указанием текущего активного режима.
